# 评测可靠性分阶段修复

本轮保持模型、20/40 次预算、课程评测器及上下文算法不变；代码与评测记录在本地提交保存。

## 实现

- `config.json` 显式配置 `request_timeout=210`，v2 默认同为 210 秒；实际等待受整轮剩余时间限制。请求/响应/错误日志记录等待上限、耗时与剩余时间。失败没有自动重试，未收到响应时用量保持未知。
- 启动器在 WSL `~/.local/state/code-agent/evaluations/run-*` 创建独立快照，课程文件逐一核对 SHA-256。原始 PDF、课程入口、Agent 和工作副本都位于原生文件系统。未采用会随本机 WSL 实例重启清空的 `/tmp` 作为持久化运行根目录。
- `bash run_long_context_v2.sh --preflight-only` 不读取密钥、不访问模型；检查 Python 3.12、pytest、patch、pdftotext、源码完整性、初始测试可运行性、课程 PDF 校验，以及三次完整提取的页数和文本哈希。
- 正式运行先通过同样预检，再加载既有本机密钥；每题只运行一次。课程即使给出 0 分，若 Agent 因通信/总时限/缺失 usage 失败，仍按基础设施问题停止下一题。普通功能失败继续下一题。
- 运行状态持续写入原生目录；结束、异常或中断时尝试归档。目标目录已存在时不覆盖；归档失败保留原生结果并报告位置。

## 重复读取诊断

上一轮真实轨迹和离线回放显示，问题并非所有重复读取都发生在证据仍完整可见的情况下：

1. 读取 `logger.py` 和 `stats_logger.py` 后，下一请求选入 `logger.py`、`environ.py`，`stats_logger.py` 的完整证据被预算排除。
2. 模型召回 `ev-000003` 后，该文件完整入模，使请求达到 31,352 字符；另两个文件的复用证据和历史动作被排除。
3. 下一轮模型重新读取另外两个文件；再次入模时它们被作为新证据选入，`stats_logger.py` 又被排除。第六个响应继续搜索该统计模块。

这证明存在跨模块证据轮换，支持后续检查按相关函数/范围保留证据、去重和阶段推进。不能只归因于模型不愿修改，也不能将本轮超时简单解释为上下文问题。本轮不改变选择策略，待新评测决定第二批改动。

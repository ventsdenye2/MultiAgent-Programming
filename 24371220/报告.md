# 迷你编码智能体：从任务到补丁

自行实现模型、工具与执行器的最小闭环；不使用现成 Agent 框架。



## 整体执行闭环

读取任务 → 模型决策 → 执行工具 → 验证交付

- 读取任务：保留题面与约束

- 模型决策：每轮一个 JSON 动作

- 执行工具：读写文件、运行测试

- 验证交付：真实日志与代码补丁



模型决定下一步做什么，程序负责参数检查、工具执行和状态更新。写入后重新验证；测试、诊断及计划全部完成，才允许正常结束。

run.log 实时记录完整请求、响应、文件内容和命令输出；上下文压缩不会删除原日志。patch.diff 根据初始快照生成，失败或中断也保存已有改动。

核心包含 agent.py 的 SYSTEM、Agent 和全部 context_selection.py，按非空、非纯注释物理行计数；CLI、API 传输、日志和底层工具另计。环境：WSL 2 / Python 3.12.3 / pytest 8.4.2 / GNU patch 2.7.6。



# 特色功能：先选信息，再压缩

Diagnostic-Driven Context Selection and Compression  /  确定性规则，无额外模型调用。



## 一次模型请求前，做四步处理

观察去重 → 诊断定位 → 相关性排序 → 预算内组装

- 观察去重：更新命令结果；
写入使旧源码失效

- 诊断定位：识别当前阶段；
提取文件、测试、异常

- 相关性排序：验证、失败、路径
匹配与近期代码优先

- 预算内组装：摘录诊断行、去重；
超长内容再保留头尾



## 当前状态决定优先保留什么

| 状态 | 判断依据 | 优先信息 |

| --- | --- | --- |

| 探索定位 | 尚未形成有效诊断 | 题面、文件列表、已读业务代码 |

| 修复失败 | 当前 pytest 或诊断返回失败 | 失败测试、异常位置、相关代码 |

| 修改后验证 | 已写入，尚未完成测试验证 | 最近改动、待验证项、历史失败参考 |

| 收尾 | 最近完整测试已通过 | 验证结果、计划完成状态 |



状态用于信息排序，不代替完成检查。收尾时仍须满足诊断通过、计划全部 done；写入前的失败不再作为当前诊断锚点。



## 预算和证据保持一致

| 固定保留 | 按相关性填入 | 始终保留在日志中 |

| --- | --- | --- |

| 系统提示、完整题面、
追加要求、计划与验证状态 | 当前诊断摘录、相关源码、
最近修改和必要工具结果 | 完整原输出；候选分数、
选择原因与实际请求内容 |



长命令输出抽取失败、断言及汇总附近原文，合并重复行。识别失败时退回头尾裁剪；长代码暂未实现函数级切片。baseline 与 diagnostic 共享提示词、工具和字符预算，仅改变上下文构造方式。



**同题、同模型、同预算，交替各跑 3 次**

主实验固定第五题，每轮使用新副本；再分别跑五题回归。deepseek-flash，温度 0，上下文 15000 字符，输出 4096 token，最多 60 步；智能体 600 秒、最终验证 120 秒。开关：--context-mode baseline|diagnostic。



# 实验结果：通过了，成本未下降

16 次真实运行全部保留；功能测试与过程检查分别报告，避免把代码正确等同于整题通过。

## 如何理解这组结果

课程仓库小、修复点集中，基线可能已经保住足够线索，任务难度未必能体现智能选择的优势。但当前诊断模式确有重复调用，重组历史也可能削弱动作与结果的连贯性。这两种可能需要分开验证。



下一步可预先设计无关日志、中段关键错误和多文件依赖压力任务，再按相同预算比较；本次不追加有利样本。温度 0 也不保证完全复现，三轮仅支持小样本观察。

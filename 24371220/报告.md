# 从任务到补丁：基础智能体

这次实践实现了一个命令行编码智能体：读取题目后，由 DeepSeek 决定下一步工具动作，程序执行并把结果送回模型，直到修改后的测试通过。代码直接调用官方 Chat Completions 接口，没有使用现成 Agent 框架。


四项基础功能的取舍


交互模式在写文件和执行命令前展示动作并请求确认；用户可以追加要求、查看计划或中断。--auto 跳过键盘输入，供评测使用。计划采用 todo、doing、done，更新时不允许改变标题和顺序，避免执行过程中丢失原目标。


读、写、命令是三项基本工具，另提供文件列表与计划更新。写入限定为题面列出的业务文件；命令只允许完整 pytest 和题目诊断脚本。工具权限较窄，牺牲了通用性，但能减少误改测试或操作项目外文件的机会。


基线模式保留完整任务、追加指令和当前计划。单条结果超过 4500 字符时保留头尾，总上下文超过 15000 字符时删除最早的动作和结果。这个方法容易实现，但中段错误或较早读过的关键代码可能被丢掉。


运行轨迹与验收


run.log 按操作实时写入完整请求、返回、文件内容和命令输出。上下文裁剪只影响下一次模型调用，不删原日志。patch.diff 由运行开始时的快照和最终代码生成，失败或中断也保存已有改动。完成动作要求修改后的完整测试通过、诊断通过且计划全部完成。


核心代码合计 288 个非空非纯注释物理行，范围为 agent.py 的 SYSTEM、Agent 和整个 context_selection.py。API 传输、底层工具、CLI、日志及补丁属于辅助代码。运行环境为 Ubuntu WSL 2、Python 3.12.3、pytest 8.4.2 和 GNU patch 2.7.6。


本次只在项目内新增依赖与实验文件，未再修改 WSL 全局配置。挂载盘的临时文件兼容问题通过项目路径内的 tmpfs 处理，运行脚本退出时卸载。


# 特色功能：按诊断选择上下文

Diagnostic-Driven Context Selection and Compression 的出发点是：先判断当前要解决什么，再决定给模型什么。第一版使用确定性规则，不增加摘要模型或检索服务，便于与原来的滑动窗口比较。


选择和压缩如何进行


每次工具执行后保存结构化观察，同一路径的重复读取和同一命令的旧结果由新结果替代。成功写入后移除该文件的旧读取版本。根据最近写入及后续验证结果，把当前状态区分为探索、修复、待验证和收尾；写入之前的失败不再作为当前诊断锚点。


从当前失败输出提取 Python 文件名、测试名和异常类型。候选记录按当前验证、失败、诊断路径匹配、写入代码、读取源码和时间新近程度加分。相关记录优先进入剩余预算，不直接压缩所有历史。


命令输出过长时，抽取失败项、断言、异常位置和汇总附近的原文，去掉完全重复的行，再对超长摘录保留头尾。无法识别的长文本回退到头尾截取。短文件尽量完整保留；第一版对长代码仍使用头尾截取，尚未实现函数级切片或跨文件依赖分析。


固定上下文仍保留系统提示、完整题面、追加要求和计划状态。context_summary 记录候选分数、原因、入选情况及实际发出的内容；原始输出另存于 command_result。实验开关为 --context-mode baseline|diagnostic，评测脚本通过 MINI_CONTEXT_MODE 传入同一选项。


实验设置


主实验固定第五题，两种模式交替各运行 3 次；每轮从新副本开始。固定 deepseek-flash、温度 0、15000 字符上下文上限、4096 输出 token、60 步、600 秒智能体上限和 120 秒验证上限。两组使用同一代码、提示词和工具，仅上下文策略不同。所有运行结果均保留。


首先看题目和过程检查是否通过，再比较 API 上报的输入 token、调用次数与时间。token 统计包含重复发送的上下文，不等同于费用；缓存命中和服务延迟也会影响实际成本。温度为 0 仍不能保证输出完全一致，三轮结果只用于小样本观察。

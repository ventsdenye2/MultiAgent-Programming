# EA-CM 上下文效率 MVP：三轮评审后的改动方案

日期：2026-11-05。当前状态：基础 MVP 已实施，完整离线回归147项通过；后续六次真实测试已完成，论文3/3通过、源码2/3通过，详见[测试报告](experiments/smolagents/mvp-3x3-20261105/REPORT.md)。通用 LLM 上下文选择功能未加入。以下方案和实施记录保留各阶段当时的状态。

以下评审正文保留原决策与当时状态，最新实现及验证见文末。

评审方式：主 agent 将上一轮完整方案交给 1 个 Astra（max 推理）子 agent，双方完成三轮独立评审、反例讨论和最终边界检查。代码基线为 `fbdfdba`；评审开始与结束时业务工作树均干净，本轮仅新增本文档。

## 目标与取舍

在保留论文任务质量、完整阅读和证据核验的前提下，减少无新需求的原文重复，并让现有 LLM 的回看需求更容易表达和可靠执行。

当前 `recall` 已由执行 LLM 决定调用。本方案不声称首次引入 LLM 决策，也不增加独立管理 Agent 或额外的上下文选择模型请求。

第一版仅包含：

1. 给自动携带和自动错误恢复设置不可续期的窗口。
2. 明确零答案、零章节时的交付缺项，及时保存已有成果。
3. 增加论文专用页码回看别名，正常轮先覆盖未读页、再用余量处理回看。
4. 对实际请求计账，分别验证机制正确和端到端效率。

暂缓 `request_context` 通用接口、动态笔记/答案加载、语义索引、证据组原子调度、重要性评分、未来完成轮次预测。五份最新主题笔记继续沿用当前加载方式；源码题调度和 DSML 协议层保持原范围。

## 一、自动重发的生命周期

复用 `pending`、`recall_ranges` 和版本化 Evidence ID，新增每页的完整确认锚点 `confirmed_anchor`。同一版本证据最多有一个未完成需求。

| 事件 | 队列与锚点行为 |
|---|---|
| 首次 `read_pdf` 登记未读页 | 保留首次覆盖需求；登记不等于送达 |
| 模型对尚未确认页再次请求 | 合并需求，不重复入队、不改变排队次序 |
| 模型对已曝光页调用 `recall`、`recall_pages` 或重读 `read_pdf` | 建立新的显式回看需求；未满足前仍只保留一项 |
| 第 N 次真实请求完整包含原文，且获得非空响应 | 对首次完整曝光或真正待确认的显式需求设锚点 N，清除已满足需求 |
| 自动 carry 或错误恢复 | 只能使用尚未过期的资格；不进入 `pending`，不更新锚点 |
| 空响应、未确认需求 | 不确认曝光，不因自动窗口到期而丢弃需求 |
| 版本失效 | 失效旧证据及对应锚点、需求元数据 |

锚点 N 只允许在 N+1 自动重发一次。N+2 起没有新的显式需求，就不能再自动发送该页。N+1 没有使用机会也不延期；反复执行 `build()` 不确认送达、不消费需求、不续期。

必须删除自动恢复调用 `request_originals()` 的旧路径。确认时先快照此前的曝光/待确认状态，再更新状态，防止恢复产生的内容被误认成新显式需求。

非空响应只提供现有审计规则所要求的送达确认，不证明模型理解了页面，也不保证随后的动作解析或执行成功。空响应下仍可能连续发送同一未确认页；这属于未完成需求重投，受总请求预算约束，不能宣称全部重复都被 TTL 消除。

## 二、调度规则

固定控制信息、必要反馈、常驻主题笔记以及简短读取回执先在预算中预留。

正常轮分两个装箱阶段：

1. **首次覆盖阶段**：按现有页码顺序装入能够容纳的完整未读必读页。遇到放不下的页，结束这一阶段，保留已经选入的页面。
2. **显式需求阶段**：用剩余空间按 FIFO 处理回看需求，不移除已经选入的覆盖页。使用独立的阻塞状态，不能继承第一阶段的 `page_blocked`。

必读范围覆盖结束后，显式需求优先，其后才考虑仍有资格的自动 carry。显式需求包括合法登记但尚未曝光的附录页，不能只筛选“已经曝光的页”。自动 carry 的既有适用范围不扩展到一般首次覆盖轮；空余空间本身不是重复发送理由。

保留一个错误恢复例外：如果上一轮动作失败，相关页仍有 N+1 自动资格，下一轮可专门恢复该批次。只能使用仍在资格内的页面；其中已经是上轮自动 carry 的过期页不能重新获得恢复窗口。第二次错误不能续期，随后回到正常调度。未确认首发/显式需求仍然可以重投，但必须按真实需求分类。

本轮实际送入的有效笔记可以替代可选 carry；显式原文请求不能仅因笔记存在被取消。

已成功的工具动作不自动重执行、不回滚。例如 `save_answer` 成功后 `write_note` 失败，答案保持已保存，后续修复失败部分；同批原文仍可获得既定的一次恢复。不新增“保存过一个成果就跳过恢复”的状态，因为这不能证明同批其他材料已经处理。

这一策略保证正常轮的回看不挤掉本轮可装入的覆盖页。它不保证任意回看下一轮必达，也不保证所有需求都能在 40 次请求内兑现。首次覆盖、页面可装入和运行错误仍然影响实际完成时间。

## 三、LLM 如何参与

论文路径新增一个短别名，既有 `recall(evidence_ids=...)` 保持：

```python
recall_pages(pages=[10, 13])
```

页码仅为接口示例，由模型依据当次材料决定。工具只有一个必填整数数组：

- 整批验证当前版本中已合法提取、已登记的页面，再修改队列。
- 拒绝布尔值、字符串、缺失或过期页面；重复页去重保序。
- 不把必读的 52 页硬编码为所有可回看的范围；合法登记的附录仍可请求。
- 只做页码到证据 ID 的解析和排队；不隐式读取 PDF、不确认曝光、不新增模型调用。
- 不强制 `question_id` 或长篇选择理由；当前问题可在正常动作说明中表达。

选择独立别名的原因是现有通用参数校验支持基础类型、必填项和数组元素，不支持二选一互斥 Schema。为了让旧 `recall` 同时接收两类可选参数而扩展通用校验器，不符合本次最小范围。新增别名说明本身的输入成本也要计账。

不常驻发送 52 行语义目录。模型利用原文 Evidence 标头和主题笔记中的页码回看；未知页面的内容继续由首次覆盖发现。

每轮紧凑反馈至少包含：

- 已保存答案 `0/10` 起的状态和缺项 ID。
- 已保存章节 `0/5` 起的状态和缺项 ID。
- 剩余请求数；本次选入页、尚待发送的显式页及等待总数。
- 最近工具返回的短保存结果，如 `section`、`question_id`、`saved`。

短回执必须预留预算，不能沿用最后“有空间才追加”的可选提示。列表可有界展示，但必须保留总数和等待状态。“本次选入”与“历史已确认送达”分开表述，均不等于已经理解。

## 四、边读边形成成果

在正常执行响应中，有足够证据就调用 `save_answer`，必要时更新主题笔记和章节，然后请求下一步确实缺少的原文；无需等待全部 52 页读完才开始保存答案。信息足够时可以直接产出，不要求每轮发起检索。

答案继续保存模型自己选择的答案值、完整支撑引用、页码和版本化证据。数组答案的引用仍须支撑全部项目。

主题笔记保留关键结论、页码、方法区别/局限与未决问题，更新时保留已有重要事实。移除当前工作流额外要求的“每篇笔记都重复两题完整引文”；精确长引文由 `save_answer` 保存。五份最新笔记继续常驻，暂不自动回送所有答案正文和长引文。

保留模型原文生成校验、先送达后引用、版本校验、全部必读页完整入模、五份最新笔记在后续同一真实请求共同出现，以及提交和验证门槛。引文字符串匹配仅证明出处，不证明语义正确。

## 五、三个可回退的实施提交

| 提交 | 修改内容 | 主要文件 |
|---|---|---|
| A | 确认锚点、不可续期 carry/recovery、实际请求选择原因 | `course_agent/evidence.py`、`course_agent/context.py`，必要的审计 sidecar |
| B | 从零显示答案/章节缺项、简短保存反馈、及时沉淀及笔记提示 | `course_agent/context.py`、`course_agent/session.py` |
| C | paper-only `recall_pages`、两阶段选择、预留短回执 | `course_agent/session.py`、`course_agent/evidence.py`、`course_agent/context.py` |

相关离线测试随提交更新。无需为了本方案改 vendor、通用 Schema 校验器或 DSML 转换流程；需要验证新别名经现有 Python/DSML 两条入口都正确到达相同业务工具。

原因分类至少分两维：主因为首次覆盖、显式需求或自动恢复/携带；是否是未确认重投单独记录。原因重叠时优先使用首次覆盖、显式需求、自动重放的顺序。重投次数可以从实际请求历史推导，不新增理解状态或语义进展评分。

这些分类放在审计记录中，不把完整审计信息再塞进模型上下文。实际 HTTP 请求体才是发送量、完整页和预算的核对依据。

## 六、机制验收

使用现有 MockTransport/真实 SDK 请求链检查完整 JSON，不只检查选择器 manifest。

| 场景 | 必须满足 |
|---|---|
| 连续解析/动作错误 | 首发或显式送达 N 后，N+2 无新需求就不再自动发该页 |
| 空响应、失败传输、重复 build | 不伪造确认、不丢未满足需求、不刷新自动窗口 |
| 重复与新显式需求 | 未完成时去重；完成后的新 recall/read_pdf 重读可以重新送达 |
| 队列溢出和非法页码 | 溢出继续等待；非法整批请求不能部分改队列 |
| 版本变化 | 旧证据、需求和锚点失效，不能引用旧版本 |
| 覆盖与回看竞争 | 除独立测试的一轮恢复例外外，已读回看不能挤掉已选覆盖页；两阶段阻塞互不误伤 |
| 跨轮比较 | 现有连续两页组合、新回看优先及 FIFO 测试仍成立 |
| 状态与部分工具成功 | 零缺项状态和短回执可见；成功保存不会因后续工具失败被重执行 |
| 完整性 | PDF 页原子、实际完整 JSON 不超过 32,000 字符；五份最新笔记共同入模门槛正确 |
| 两种协议 | Python 和 DSML 调用页码别名均经过原有校验/执行/审计 |

已有恢复测试中“动作失败后旧页必须重新进入 pending”的断言属于内部实现，需改为检查一次恢复的实际 HTTP 行为，不能为了满足旧断言保留无限续期路径。

窄范围回放夹具：旧样本 R23 完整确认第 51、52 页，此后没有新需求时，最多 R24 自动携带；R25–R27 不得再自动发送它们。两页原文分别为 3,844 和 4,072 字符，这段固定重复是 `3 × (3844 + 4072) = 23,748` 字符。

该数字是固定动作轨迹中可以禁止的原文重复，排除标头与 JSON 包装；不是已实现的新测试结果，也不是未来真实运行节省量或 token 预测。旧样本后期还存在合理显式回看，不能把后期所有重复都算成可节省。

诊断轨迹：`experiments/smolagents/context-20261105-p0-a-3x3/static/samples/paper-01/evaluation/paper/development/run.log`。该旧版本与当前 DSML 设置不同，只作机制夹具，不直接作为新真实实验基线。

## 七、真实效率验收

机制验收通过后，以当前 `fbdfdba` 配置和完整 MVP 做真实对照。模型、服务、DSML 开关、静态提示压缩开关、题面、评测器和请求预算保持一致，仅保留已声明的 MVP 差异。

预先登记至少三对运行，交替基线/MVP 的先后顺序，每次从干净任务副本和空会话开始。可先执行第一对作烟测；若据此修改实现，旧组完整归档，新版本重新冻结确认组。不能不断补跑并剔除失败对来凑出三对成功样本。

预定工程门槛：

1. MVP 三次均满足全部课程条件并取得论文题 5/5 分，才称本确认组完成任务。
2. 只有预定三对中双方都完整通过、质量相同时，才检验同质量输入效率。
3. MVP 的真实输入 token 合计至少降低 10%，至少两对下降，实际请求次数合计不增加。
4. 所有实际请求及题面、工具说明、笔记、回执、错误恢复等输入都计入；同时报告重复原文字符、首次答案轮次、首次全文覆盖轮次、分数和耗时。
5. 所有请求 usage 必须完整，检查 `audit.totals().complete`。缺失不能计为零；字符计量可另报，不能替代真实 token 门槛。

10% 是事先确定的工程筛查阈值，不是效果预测或统计稳定性证明。三对实验不能支持广泛泛化结论。

若基线失败而 MVP 成功，可以报告这组的完成率改善及真实用量，但同质量效率证据不足，不能给出同质量节省百分比。MVP 提前失败即使输入减少也不通过。全部尝试都保留。

不要求每个提交都重复完整付费矩阵。基线与完整 MVP 可以先判断整套方案是否有用；若要单独声称页码接口/调度改善了 LLM 决策效率，再补提交 B 与 C 的同配置对照。不能把全套修复收益归给 LLM 选择本身。

## 三轮讨论记录与结论边界

| 轮次 | 主要讨论 | 收敛结果 |
|---|---|---|
| 1 | 上一轮通用内容选择是否过大；主要成本在哪里 | 收窄为有界重发、及时保存、简单回看；保留现有笔记加载，暂缓预测和语义状态 |
| 2 | 错误恢复是否立即让位覆盖；接口是否扩展旧 recall | 保留一次不可续期恢复；使用页码别名；分清原文重发和工具动作重执行 |
| 3 | 队列续期、页阻塞、回执预算、附录需求与实验口径 | 删除恢复入 pending 的旧路径；两阶段装箱；预留回执；不漏合法显式需求；不挑成功样本、不隐藏缺失 usage |

可确定性证明：自动窗口不续期、未确认需求不丢、显式重读可重新送达、正常覆盖不被可选回看挤掉、原子页与预算、最新笔记共同入模，以及指定固定轨迹中的重复被禁止。

仍须真实实验验证：LLM 是否更早保存正确成果、完整任务是否减少总输入、是否减少请求，以及完成率是否改善。

本轮交付为评审与改动方案；未修改业务实现、未运行新的回归测试、未启动付费评测。

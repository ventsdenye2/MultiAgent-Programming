# P0 / A 固定版本对照

## 范围与授权

用户确认两道题、两版本、每题每版本各 3 次，共 12 个样本；另明确同意将题面、论文摘录、源码和运行反馈发送至 `https://api.deepseek.com`，使用 `deepseek-flash`。源码每轮最多 20 请求、论文 40，总上限 360。失败不替换、不自动重试。

实现检查点 `c6a220590163bf8d8be1d1db8436b78935301b27`。本地 106 项离线回归通过，vendor 24 文件一致。既有材料迁移修改未混入实现提交；实际评测入口的哈希单独记录在 comparison.json。两组冻结运行文件相同，配置只差 static_context_compact；P0 分项计量均开启。默认应用配置仍为基线。

## 固定条件

- 模型、采样、Markdown Python 输出协议、课程题面、验收器、预算和 EA-CM 动态选择算法不在本批内修改。
- baseline/static 源码论文交替顺序固定于 comparison.json；每组 study.json 保存配置与运行文件哈希。
- 每次开始及完成都核对冻结输入；基础设施失败会停止自动调度，人工检查后才继续剩余未开始样本。
- 原始 HTTP 请求/响应、usage、context_accounting、执行事件、补丁、官方结果分别保留。失败样本同样保留，缺失 usage 不估算。
- 静态字符减少不等同于总 token 减少：节省空间可能被动态证据填充；比较实际每请求分项、总请求数、总 usage 和完成率。

## 运行中观察

- baseline/source-01：20 请求，4 次协议解析错误；后续修改及 pytest 成功，但未正常结束，预算耗尽。完整失败保留。
- static/source-01：19 请求，完整通过，课程得分 1/1；1 次协议解析错误。不能用单个样本宣布稳定或消除协议问题。
- DSML 响应与 Python 代码块解析不匹配是历史已知问题；本批不加入转换器或静默修写原始输出，避免与 A 混淆。

## 分析产物

summarize_context_comparison.py 只读归档并写入新的 analysis-* 目录，输出 CONTEXT-COMPARISON.json 与 REPORT.md。部分快照只代表当时进度，最终结论须基于全部已结束样本；包括已知 token、缓存命中、请求时间与响应延迟、逐请求字符归属、修改/测试/结束位置和错误计数。

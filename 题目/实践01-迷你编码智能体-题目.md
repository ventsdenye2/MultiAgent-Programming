# 第一次实践：造一个迷你编码智能体

单人完成，课堂90分钟搭骨架，课后一周完成全部内容。公开任务与测试随题目发放。

## 一、任务概述

从零写一个命令行编码智能体。它接收任务描述和代码仓库，自主完成读代码、改代码、跑验证，最终交出补丁。核心循环为150～300行Python，必须自行实现，不许基于现成agent框架（如LangChain Agents、AutoGen等）搭建。

本实践对齐第1讲编码智能体的结构剖析：只有亲手实现一遍模型、工具、执行器、上下文的最小闭环，后面各讲谈检索、多智能体、评测时才有切身体感。

## 二、最终评测模型

选择 DeepSeek 或 Qwen，确定实际模型名后全程固定，报告中注明：

- DeepSeek：优先使用 `deepseek-flash`；接入服务支持时，也可使用兼容名称 `deepseek-v4-flash`
- Qwen：`qwen3.8-flash`

使用课程统一中转API，也可使用模型官网API。config.json 必须提供 model、base_url 和 key_env，分别填写模型名、API根地址和密钥环境变量名；--model 与配置及实际请求一致。接入与示例见 [使用说明](../README.md#模型接入)，不限定SDK或API通信格式。

## 三、必须完成的功能（四项）

1. 用户交互。命令行多轮对话：用户下达任务、追加指令、查看进度、中断执行。agent执行写文件和跑命令前，须展示将要执行的动作（可提供自动确认模式供评测使用，但交互模式下默认要求人工确认）。
2. 基本上下文管理。自行组织对话历史，并实现至少一种超长上下文应对策略（截断、滑动窗口、历史摘要任选）。报告中必须写清：触发条件是什么、被丢掉的是什么、为什么这样取舍。
3. 基本任务管理。对多步任务能拆解为子目标并跟踪状态（todo列表或等价机制），用户随时可以查看当前进度和已完成项。
4. 基本工具集。至少三个工具：读文件、写文件、执行命令。工具的参数约定和返回格式自己设计。

## 四、自选特色功能（一项，必须是自己提出的）

在基础功能之外提出并实现一个功能，在≤3页报告正文中用约一页篇幅说明：它解决什么真实痛点、怎么设计、效果如何。效果必须给出实际测试结果。
参考方向（不限于此）：
- 命令执行失败后的自动重试与错误归类
- 提交补丁前先自动跑测试，失败则继续修
- 按任务关键词检索仓库、只把相关文件放进上下文
- token成本实时统计与预算熔断
- 计划与执行分离的双角色结构

须实现特色功能，并说明动机、设计与对照实验；特色功能不单独计分。

## 五、统一接口约定（评测的硬性要求）

所有agent必须支持以下启动命令，评测脚本会自动调用：

```bash
python agent.py --task task.md --repo <仓库路径> --model <模型名> --auto
```

| 命令部分 | 含义与要求 |
| --- | --- |
| `python` | 使用当前环境中的Python解释器运行程序。 |
| `agent.py` | 你自行编写的智能体启动文件，负责接收这些参数并启动智能体。其他实现代码可以拆分到多个文件中。 |
| `--task task.md` | 指定要读取的题目文件。将`task.md`换成本轮题目文件的实际路径，例如`../work/task.md`。 |
| `--repo <仓库路径>` | 指定本轮工作代码所在的文件夹，智能体在这里读代码、改代码、运行测试。填写自测副本的路径，例如`../work/repo`。 |
| `--model <模型名>` | 指定本次使用的模型，例如`deepseek-flash`。必须与`config.json`中的`model`及实际请求的模型一致。 |
| `--auto` | 开启自动运行模式，不需要在后面填写值。开启后全程自动执行，不等待键盘输入或人工确认。 |

尖括号中的内容需要替换为实际值，尖括号不要保留。`agent.py`也可以写成它的绝对路径；相对路径以当前终端所在目录为准。完整的准备与运行步骤见 [公开任务自测](../README.md#公开任务自测)。

- 自行实现的agent负责将改动写入仓库，并在启动目录生成`patch.diff`与`run.log`；评测工具负责检查这些文件
- `run.log`须包含完整轨迹：每轮发给模型的内容、模型返回、工具调用与结果，不删减
- `--auto`需要自己实现

接口不合格的公开题记0分；日志协议和评分方式见 [使用说明](../README.md)。

## 六、测试用例与评测方式

公开发放5个测试用例用于开发和自测，每个用例包含：仓库快照、task.md、可见的pytest验证脚本。5个用例各对应观测一项能力：

1. 埋点bug修复。单文件、缺陷明确，测最基本的读改闭环（热身题）。
2. 新增功能加回归。按规格给模块新增一个函数，既有测试必须保持通过，测不破坏旧功能。
3. 跨文件定位。bug所在的文件不在task.md中指明，需自行搜索定位，测检索策略。
4. 双子任务。一份task.md含两个有依赖关系的子任务，测任务拆解与进度跟踪。
5. 长日志修复。需要跑测试、阅读较长的失败输出再定位修复，测上下文管理策略是否真起作用。

按 [自测说明](../README.md#公开任务自测)，可以用 run_eval.py 一次评测五题，也可以手动逐题创建副本、运行智能体、检查测试与产物。两种方式使用相同的题目与评分要求。

## 七、提交物

1. 以学号命名的代码仓库，含agent.py、config.json、全部实现和README（写清依赖、接入与运行方式）；见 [提交材料](../README.md#提交材料)和[模型配置](../README.md#模型接入)
2. 报告，不超过3页：总体设计、四项基础功能的实现取舍、特色功能及对照实验、5个公开用例的自测跑分表
3. 至少一次公开用例的完整`run.log`

## 八、评分细则（五分制）

只统计五道公开题，总分5分。每题通过得1分，未通过得0分，不折算部分分；例如通过三题得3分，五题全部通过得5分。

通过要求为入口正常退出、完整测试全部通过，且日志、补丁、修改范围和题面过程检查合格。功能演示、特色实验、报告和真实轨迹须按要求提交，这些项目不单独计分。详细规则见 [使用说明](../README.md#五分制评分)。

## 九、规则与边界

- 核心循环（消息组织、工具调用解析、循环控制）必须自行实现；可以参考教程和文档，报告中注明参考来源。直接调用现成agent框架的高层封装视为未完成作业。
- 轨迹必须真实。`run.log`伪造、事后补写、人工代改后冒充agent产出的，本次实践记零分。
- 允许也鼓励在交互模式下与自己的agent协作开发它本身，但评测以`--auto`模式为准。

核心行数包括消息组织、动作解析、循环控制、计划调度和上下文处理，拆分文件也须合计；底层工具等辅助代码另计。行数与附件要求见 [提交材料](../README.md#提交材料)，测试步骤、先后顺序和时间限额见[必须遵守的规则](../README.md#必须遵守的规则)。
